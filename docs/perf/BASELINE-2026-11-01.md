# Performance baseline, 2026-11-01

The first measurement of V2. The goal of the rewrite was a lean bot: the first bot asked for a
6 GB heap, and antho-s-bot used about 296 MB (220 MB of it Next.js).

**Machine:** AMD Ryzen 7 9800X3D (16 threads), 30 GB, CachyOS (Linux 7.3). **Build:** `--release`
(opt-level "s", thin LTO, panic=abort, stripped). **Mode:** `bot preview`, all 15 features on:
two sample servers seeded in memory, no Discord connection. Render's instance is much smaller and
shared, so treat the times as relative, not as what Render does.

## Memory

| | VmRSS | Threads |
|---|---:|---:|
| After boot, idle 3 s | 20.2-20.6 MB | 3 |
| After serving all 27 pages 46 times each | 21.6-23.5 MB | 3 |

The live bot adds the gateway connection and its cache (members, channels, last 25 messages per
channel) for the real servers; this doesn't measure that.

## Dashboard pages (server side)

`python3 docs/perf/measure.py`: one signed-in person clicking through every page on a kept-alive
connection, 40 timed requests per page after 5 warm-ups. This is closed-loop service time on
localhost; it doesn't model load or the network.

| | Before (no compression) | After (gzip, fastest) |
|---|---:|---:|
| All 27 pages, bytes sent | 1,259 KB | 345 KB (3.6x less) |
| Largest page (`pets`) | 75 KB | ~15 KB |
| Median page p50 | 0.28 ms | 0.30-0.34 ms |
| Slowest page p95 | 0.89-0.98 ms | 0.77-0.79 ms |
| `app.css` / `app.js` sent | 74 KB / 44 KB, cached 1 h | 24.5 KB / 18.8 KB, cached 1 year, versioned |

Every page renders in under 1 ms, so the cost a person feels is the network. The default gzip
level was also measured: 256 KB for all pages, but +0.6 ms of CPU per page (p50 0.88 ms). On
Render's small shared CPU that isn't worth ~3 KB a page, so the fastest level is used.

Static files are linked as `/static/app.css?v=<hash>`, so they can be kept for a year and a new
build is picked up at once (before, a deploy could pair new pages with an hour-old `app.js`).

Not changed: the Google Fonts stylesheet is render-blocking on a cold cache (two more origins
before first paint). Self-hosting Geist would remove that; it's a first-visit cost only.

## One member message, every feature

`cargo run --release -p bot --example message_cost -- 20000`: synthetic chat messages from the
sample members through every feature's `on_event`, as the gateway dispatch does.

| | |
|---|---:|
| Per message, all 15 features | p50 9.0 µs, p95 12.2 µs, p99 16.8 µs |
| guard (scam scoring) | ~4 µs |
| utility (AFK lookup) | ~4 µs |
| everything else | < 0.25 µs each |

At 100,000 messages a day that is about a second of CPU. XP isn't written per message. The one
outlier (124 ms) was a seeded AFK member coming back: the bot tries to restore their nickname
and post "welcome back" through Discord, which is the feature working.
